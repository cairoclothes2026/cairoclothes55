# إعداد أول مدير للمنصة

صفحة إدارة طلبات المحلات موجودة في `/ar/admin` و`/en/admin`. لا تسمح الصفحة بإنشاء حساب مدير أو رفع صلاحية الحساب؛ يضيف مالك مشروع Supabase أول مدير يدويًا.

## الخطوات

1. طبّق ملفات `supabase/migrations` بالترتيب. إذا كانت الترحيلات السابقة مطبقة بالفعل، شغّل `0010_admin_bulk_store_actions.sql` في Supabase SQL Editor.
2. اختر بريدًا موثوقًا للمدير. يجب أن يكون الحساب قد سجّل الدخول إلى المشروع مرة واحدة حتى يظهر في `Authentication → Users` وينشأ صفه في `public.profiles`.
3. في SQL Editor، استبدل البريد في الاستعلام التالي بالبريد المختار، ثم شغّله:

```sql
update public.profiles as p
set role = 'admin'::public.app_role
from auth.users as u
where p.id = u.id
  and lower(u.email) = lower('admin@example.com');
```

تحقق من أن النتيجة عدّلت صفًا واحدًا. إذا لم يتغير أي صف، فتأكد أن هذا البريد سجّل الدخول وأنه مطابق للحساب الموجود في `Authentication → Users`.

4. افتح `/ar/admin` أو `/en/admin`، وأرسل رابط الدخول إلى البريد المعيّن مديرًا.

## ضوابط المراجعة

- يمكن للمدير عرض كل طلبات المحلات بكل حالاتها واعتماد أو رفض أي طلب معلّق.
- زر القبول الجماعي يعتمد كل الطلبات المعلّقة عدا طلب المحل المملوك لحساب المدير.
- «إزالة الكل من الموقع» تخفي المحلات من الاكتشاف دون حذف بياناتها، وتسجّل الإجراء في سجل الإدارة. يمكن إعادة كل محل مخفي إلى حالته السابقة من بطاقته.
- عند الاعتماد، تصبح حالة المحل `active` ويظهر في الدليل العام. كل قرار يُكتب في `platform_audit_log`.
- لا يستطيع المدير اعتماد طلب محله أو رفضه؛ يجب أن يراجعه مدير آخر.
- منح دور المدير أو سحبه مسؤولية مالك المشروع داخل Supabase SQL Editor؛ لا تكشف الصفحة صلاحية رفع الدور.
- الحسابات العادية لا تستطيع عرض كل الطلبات أو اعتمادها أو رفضها.
